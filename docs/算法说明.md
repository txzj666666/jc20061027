# 算法说明

本文给出系统两个核心算法的完整定义：**① 人脸情绪识别**、**② 情绪驱动的歌曲推荐**。
所有公式都在代码里有对应实现与逐行注释，本文标注了文件与函数位置，便于对照阅读。

---

## 一、人脸情绪识别算法

### 1.1 模型选型

| 阶段 | 模型 | 结构 | 输入 | 输出 | 权重大小 |
| --- | --- | --- | --- | --- | --- |
| 人脸检测 | **Tiny Face Detector**（`tiny_face_detector_model`） | MobileNetV2-SSD 单尺度轻量版：4 个 depthwise-separable 模块 + 5 个 1×1 卷积预测框 | 320×320×3 RGB | 每张人脸 `{box(x,y,w,h), score}`，NMS 去重 | 190 KB |
| 表情分类 | **Face Expression Network**（`face_expression_model`） | MobileNet-V1 风格：8 组 depthwise-separable 卷积（stride 递减，通道 32→64→128→256→512）+ 全局平均池化 + 1 层全连接 | **64×64×1 灰度**人脸裁剪图 | 7 维 logits → softmax 概率 | 320 KB |
| 关键点（可选） | Face Landmark 68 | 8 组 depthwise-separable 卷积 + FC(136) | 48×48×3 | 68 点 (x,y) | 350 KB |

7 类情绪标签顺序（`src/config/emotions.js: EMOTION_ORDER`，与模型输出严格一致）：

```
neutral  happy  sad  angry  fearful  disgusted  surprised
 中性     开心   悲伤  愤怒    恐惧      厌恶       惊讶
```

> **为什么是 face-api.js？**
> ① 纯前端可跑（TensorFlow.js WebGL/CPU 后端），满足"不上传人脸"的硬约束；
> ② 表情模型直接输出 7 类基础情绪概率分布，不需要自己训练/转换模型；
> ③ 权重合计不到 1 MB，冷启动 < 1s，适合 Web。

### 1.2 单帧推理管线（`src/core/faceEngine.js: detectFaces`）

```
源画面 (img / video / canvas, W×H)
  │ 1. letterbox：等比缩放到 320×320 正方形离屏 canvas，黑边补齐
  │    scale = min(S/W, S/H)，偏移 ox=(S-W·scale)/2, oy=(S-H·scale)/2
  ▼
TinyFaceDetector → 归一化人脸框 + score
  │ 2. 坐标逆变换：work 像素 → 源图归一化坐标
  │    x_src = (x_work − ox)/dw ，w_src = w_work/dw
  ▼
按框裁剪 → 64×64 → 灰度化（0.299R+0.587G+0.114B）→ 归一化
  ▼
Face Expression Net → 7 维 logits → softmax
  │    p_i = exp(z_i) / Σ_j exp(z_j)
  │    （face-api 内部完成；本层再除一次 Σp_i 做数值兜底，保证是分布）
  ▼
质量门控 frameUsable() → 有效帧 / 丢弃
  ▼
时序聚合器 emotionTracker.push()
```

主脸选择：按 `areaRatio × score` 降序，取第一个 —— 离镜头最近且最可信的人通常是使用者本人。

### 1.3 有效帧质量门控（4 个条件，全部满足才参与投票）

| 条件 | 阈值（默认） | 理由 |
| --- | --- | --- |
| 人脸检测分 `score` | ≥ 0.45 | 低于此值时表情网络常对"非脸纹理"输出荒谬结果 |
| 人脸面积占比 `w×h` | ≥ 0.006 | 64×64 输入若来自 <20px 的脸，等于把噪声放大 |
| 清晰度（拉普拉斯方差） | ≥ 0.08 | 见下式 |
| 头部倾斜角（双眼连线） | ≤ 35° | 大侧脸时表情特征点位移方向失真 |

清晰度用经典的 **Variance of Laplacian**：

```
L(x,y) = I(x−1,y) + I(x+1,y) + I(x,y−1) + I(x,y+1) − 4I(x,y)
blur   = min(1, Var(L) / 0.05)          // 人脸区域缩放到 64×64 灰度后计算
```

倾斜角：`tilt = |atan2(y_leftEye − y_rightEye, x_leftEye − x_rightEye)|`（68 点中的 36 / 45 号点）。
未启用关键点模型时 `tilt = 0`，该门控自动放行。

### 1.4 时序聚合与稳定判定（`src/core/emotionTracker.js`）

单帧 Top-1 精度在 FER-2013 水平只有 65%~72%，且逐帧 argmax 会让标签高频抖动。
本系统在模型之上加了一层**轻量时序滤波器**：

**（1）一阶指数滑动平均 EMA（IIR 低通）**

```
S_t = (1 − α)·S_{t−1} + α·P_t ，α = 0.30 ，随后重新归一化使 Σ S_t = 1
```

等效记忆长度 ≈ 1/α ≈ 3 帧（300ms @10fps）。α 越大越"跟手"、越小越平滑，设置面板可实时调。

**（2）滞回切换判定（Schmitt 触发器思想）**

```
候选 c = argmax(S_t)
仅当  S_t[c] ≥ S_t[L] + margin(c, L)   连续满足 N = 6 帧，才把确认标签 L ← c
margin(默认) = 0.06
margin(易混淆对) = 0.06 − 0.02 = 0.04      // 恐惧↔惊讶、愤怒↔厌恶、悲伤↔中性、中性↔厌恶
```

对易混淆对**放宽**阈值，是为了让分类器确实想切换时能快速切过去，避免两个标签互相"顶死"在滞回带里。

**（3）置信度与强度**

```
conf      = 0.65·S_t[L] + 0.20·mean(detScore) + 0.15·mean(blur)
uncertain = conf < 0.45                        // 触发推荐环节的保守回退
intensity = 1 − S_t[neutral]                   // 情绪浓淡，用于文案与能量上限
```

**（4）丢帧处理**：连续 `faceGraceFrames = 12` 帧内无人脸只让 `S_t` 以 0.96 的系数缓慢衰减（约 2s 自然回落），
不立即清空，避免"手抖挡了一下镜头"就丢失情绪结论。

**（5）单帧模式**（图片上传 / 拍照）：没有时间序列可用，`EmotionTracker.fromSingleFrame()`
把单帧概率分布折算成同一套输出结构（`settled = true`），推荐层无需为不同采集方式分叉。

### 1.5 输出契约

```js
{
  label,            // 确认后的情绪标签（滞回状态机的状态）
  smoothed: [7],    // 平滑后的概率分布 —— 推荐给算法用这个，而不是硬标签
  distribution,     // 按概率降序的 7 项，UI 概率条
  confidence,       // 0~1
  uncertain,        // 置信度不足标记
  intensity,        // 1 − P(neutral)
  settled,          // 是否已稳定（滞回条件满足）
  frames, missCount, avgDetScore, avgBlur,
  history: [{t, probs[7], label}]   // 最近 24 帧，用于堆叠时序图
}
```

### 1.6 性能与已知局限

* WebGL 后端：检测 + 表情约 10~25ms/帧（i5 级核显，320 输入）；CPU 后端实测约 100~1000ms/帧。
  循环按 `intervalMs = 100` 节流，理论上限 10 FPS，实际取 `min(10, 1/推理耗时)`。
* 冷启动会额外跑一次空白帧预热（触发 shader 编译），避免首帧耗时污染统计。
* 局限：单帧模型对**微表情、文化性表情抑制、深肤色/极端光照、戴口罩**准确率下降明显；
  本系统用「多帧聚合 + 置信度回退 + 软混合推荐」把误差的影响从"推错歌"降级为"推得保守"。
* 不做身份识别（无人脸库、无 face embedding），只输出情绪，符合最小化采集原则。

## 二、情绪 → 歌曲推荐算法

**定位**：基于内容（content-based）的情绪匹配推荐。不依赖账号与历史行为，
因此离线可用、结果可解释（每首歌给出打分构成）。
实现：`src/core/recommender.js`；参数：`src/config/app.js: recommendConfig`；映射表：`src/config/emotions.js`。

### 2.1 Step 1 —— 目标向量构造（软混合）

识别端给的是 7 维分布 `p = S_t`。置信度不足时与中性做保守混合：

```
p' = uncertain ? 0.5·p + 0.5·onehot(neutral) : p        （再归一化）
```

由 `p'` 直接算出连续目标量（Russell 情绪环状模型 + 节奏目标）：

```
valence* = Σ_i p'_i · valence_i          ∈ [−1, 1]   效价（愉悦度）
arousal* = Σ_i p'_i · arousal_i          ∈ [−1, 1]   唤醒度（兴奋度）
bpm*     = 60 + (arousal* + 1)/2 × 90    ∈ [60, 150] 目标节奏
genres*  = ⋃ genres(e_i)   s.t. p'_i ≥ 0.2            情绪-曲风映射表并集（带权重）
keywords*= 同理，用于在线 API 检索词
```

情绪 → (valence, arousal) 与曲风映射表（节选，完整见 `config/emotions.js`）：

| 情绪 | valence | arousal | 目标 BPM 区间 | 映射曲风 genres | 在线检索词 keywords |
| --- | --- | --- | --- | --- | --- |
| 开心 | +0.80 | +0.55 | 105–130 | pop / funk / disco / edm / bossa nova | 欢快、治愈系、好天气、劲舞 |
| 悲伤 | −0.75 | −0.45 | 58–82 | ballad / 抒情 / piano / folk | 治愈、钢琴曲、深夜、慢歌 |
| 愤怒 | −0.60 | +0.85 | 120–160 | rock / metal / hiphop / trap | 摇滚、说唱、燃、健身 |
| 恐惧 | −0.55 | +0.60 | 60–85 | ambient / post rock / 古典 | 纯音乐 安宁、睡前、冥想 |
| 厌恶 | −0.55 | +0.25 | 92–116 | indie / bossa nova / city pop | 清爽、city pop、午后 |
| 惊讶 | +0.20 | +0.90 | 118–150 | edm / classical / soundtrack | 史诗、电子、燃向 |
| 中性 | 0.00 | −0.05 | 70–100 | lofi / 轻音乐 / jazz / pop | 轻音乐、lofi 纯音乐、通勤 |

> 软混合的实际效果：识别到「开心 0.55 / 惊讶 0.30」时，`valence*`、`arousal*` 会落在两者之间，
> 且 `genres*` 同时包含流行电子与古典/原声，列表不会完全被单一检索词垄断。

### 2.2 Step 2 —— 逐曲打分（5 个可解释分量）

每首歌 `s` 有内容特征：情绪隶属度向量 `mood_s`（7 维）、环状坐标 `(v_s, a_s)`、`bpm_s`、`rating_s`、播放次数 `playCount_s`。

```
score(s) = w₁·MoodSim + w₂·CircumplexSim + w₃·EnergyFit + w₄·Popularity + w₅·Freshness
默认权重： w₁=0.35  w₂=0.25  w₃=0.15  w₄=0.15  w₅=0.10   （Σw = 1，各项 ∈ [0,1]）
```

**① MoodSim —— 情绪标签匹配（核心）**

```
MoodSim = 0.7 · cos(p', mood_s) + 0.3 · GenreOverlap(genres*, genre_s)

cos(a,b) = a·b / (‖a‖·‖b‖)
GenreOverlap = mean( 命中数/min(|genres*|,|genre_s|) ,  命中权重/总权重 )
   匹配规则：小写去空格后双向子串命中（'indie pop' ↔ 'pop'、'轻音乐' ↔ '轻音乐/纯音乐'）
```

**② CircumplexSim —— 环状模型距离**

```
CircumplexSim = 1 − ‖(valence*, arousal*) − (v_s, a_s)‖₂ / (2√2)
```

处理"标签不同但听感接近"的情况：识别为恐惧时，`ambient` 与 `post-rock` 没有共同标签，
但环状坐标都在 (−0.5, +0.6) 附近，仍能入选。

**③ EnergyFit —— 节奏/能量匹配**

```
EnergyFit = 1 − min(1, |log₂(bpm_s / bpm*)|)      // bpm_s 未知(=0) 时取 0.5 中性分
```

用**八度（倍频）**作尺度，符合听觉感知：目标 110 BPM 时，
96 BPM ≈ 0.94，128 BPM ≈ 0.90，60 BPM = 0（差一个八度视为完全不合适）。

**④ Popularity —— 热度先验**：`rating_s ∈ [0,1]`（本地库人工/生成标注，在线按平台热度归一）。

**⑤ Freshness —— 新鲜度**：`exp(−playCount_s / 2)`，刚播过的歌快速衰减，配合"换一批"实现探索。

**来源系数（"本地优先"的量化形式）**

```
final = score × SOURCE_BOOST[source]      local = 1.00 ，online = 0.85
```

在线曲目的 `mood/genre` 是由检索词反推的（用"轻音乐"搜来的歌当然像轻音乐），存在循环论证偏差，
因此统一打折 —— 这保证同等匹配度下本地曲库排在前面。

### 2.3 Step 3a —— MMR 多样性重排

贪心取 Top-K 会返回一堆同质曲目（12 首全是 lofi）。改用 **Maximal Marginal Relevance**：

```
S ← ∅
重复 K 次： s* = argmax_{s ∉ S} [ λ·score(s) − (1−λ)·max_{s'∈S} sim(s, s') ] ，λ = 0.70

sim(a,b) = 0.5·cos(mood_a, mood_b) + 0.5·(1 − ‖(v_a,a_a)−(v_b,a_b)‖₂ / 2√2)
```

λ→1 退化为纯相关性，λ→0 追求极大差异；0.70 是"相关为主、避免重复"的经验折中。

### 2.4 Step 3b —— 情绪调节轨迹（Musical Mood Regulation）

推荐不只是"匹配当前情绪"，还承担**引导情绪回落/上扬**的作用。
实现方式：MMR 每选一首，就用"移动后的目标"重新打分：

```
valence*_j = clamp(valence* + slope·j, −1, 1)          j = 槽位序号
slope(sad)  = +0.06   → 先共情（贴合低落），随后逐首抬亮，避免"越听越丧"
slope(angry)= −0.05   → 先高能量宣泄，同时 arousal* 以 0.5·slope 递减 → 逐步平复
其他情绪 slope = 0     → 纯匹配
```

前端推荐理由里会显式打出「情绪调节：本曲效价更亮，用于逐步振作」，让策略对用户可见。

### 2.5 Step 3c —— 本地/在线混合与降级（`mix()`）

```
slots = 12 ；localQuota = round(12 × 0.7) = 8 ；remain = 12 − 已选本地数
1) 本地池 MMR 取 8 首        （本地优先）
2) 在线池去重后 MMR 补 remain 首
3) 穿插排布：在线歌均匀散布在本地歌之间（第 ⌈(i+1)·T/(n_online+1)⌉ 位），
   避免"整屏外链卡片"或"全部堆在列表尾部"
4) 在线不足/关闭/失败 → 用本地次优曲目回填到 slots 首
5) 去重键：normalize(title) + normalize(artist)，本地已有同名歌不再出在线版本
```

降级链（任一环节失败都不会让页面空掉）：

```
jamendo(未配 client_id) → 报错并提示 → 仅本地曲库
meting 主实例 → 代理实例 → injahow 实例 → 仅本地曲库
在线全部失败 → 12 首全本地；本地也为空 → 明确错误提示 + 引导执行 npm run music
音频 403/超时 → 标记「不可播」→ 自动跳下一首（连续上限 5 次）
```

### 2.6 端到端伪代码

```python
frame = capture(mode)                                  # 图片/视频/摄像头/拍照
faces = TinyFaceDetector(letterbox(frame), 320, thr=0.35)
p     = ExpressionNet(crop64_gray(faces[0]))           # softmax, 7 维
if usable(faces[0]):                                   # 4 项质量门控
    S = normalize((1-α)·S + α·p)                       # EMA
    L = hysteresis(S, L, margin=0.06, N=6)             # 滞回确认
snap = {label:L, smoothed:S, confidence, uncertain, intensity}
if L changed and settled:
    target = buildTarget(snap)                         # 软混合 → v*, a*, bpm*, genres*
    local  = [score(s, target) for s in 本地曲库]
    online = [score(s, target) for s in 在线API(target.keywords)]
    playlist = MMR(local, 8, λ=0.7, trajectory) ++ MMR(online, 4, λ=0.7)
    interleave_and_dedupe(playlist)                    # 本地优先 + 在线穿插
    player.load(playlist)
```

### 2.7 参数速查（设置面板可热改）

| 参数 | 默认 | 调大的影响 |
| --- | --- | --- |

| `faceConfig.scoreThreshold` | 0.35 | 误检↑、漏检↓ |
| `faceConfig.intervalMs` | 100 | 更省电/更跟手（100ms≈10fps 上限） |
| `trackerConfig.emaAlpha` | 0.30 | 响应更快、抖动更多 |
| `trackerConfig.stableFrames` | 6 | 切换更"稳"、延迟更大（600ms@10fps） |
| `trackerConfig.switchMargin` | 0.06 | 更抗抖动，但可能锁死在旧情绪 |
| `recommendConfig.weights.*` | 0.35/0.25/0.15/0.15/0.10 | 见 2.2 |
| `recommendConfig.mmrLambda` | 0.70 | 列表更相似（1）/ 更多样（0.3） |
| `recommendConfig.localRatio` | 0.70 | 本地槽位占比；设 1 即纯本地 |
| `recommendConfig.slots` | 12 | 歌单长度 |
| `regulateSlope.sad / angry` | +0.06 / −0.05 | 情绪引导强度，设 0 即纯匹配 |
